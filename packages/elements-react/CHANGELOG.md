## 1.0.0-beta.1

### Major Changes

- c486df4: Added the payments `branding` element — the "Powered by Whop" notice with terms and privacy links. It is required: the other payments elements stay in their loading state until it is mounted, and payments cannot be confirmed without it — a missing branding mount fails `createConfirmationToken` with the coded `BRANDING_NOT_MOUNTED` error, and one the embedding page hides or shrinks away fails with `BRANDING_HIDDEN`. Breaking for existing payments integrations: mount `branding` alongside your other payments elements when you upgrade. ([#24974](https://github.com/whopio/whop-monorepo/pull/24974))
- required element "branding" added — existing consumers must now mount it (`payments.branding`)

### Minor Changes

- c486df4: The checkout offers one-press express checkout: Apple Pay and Google Pay buttons above the form, shown when the wallet is available on the buyer's device and the page's origin is approved for the account. The wallet sheet collects whatever the checkout still needs — the buyer's email, and the shipping address when the purchase requires one — and the buttons stack best-first for the browser: Apple Pay first on Safari and iOS, Google Pay first elsewhere. ([#24974](https://github.com/whopio/whop-monorepo/pull/24974))
- c486df4: Added the express checkout element — one-press Apple Pay and Google Pay buttons you can mount on their own under a checkout handle (`checkout.create("expressCheckout")`, or `<ExpressCheckoutElement/>` in React). The OS payment sheet collects the buyer's email and shipping address when the session needs them, so one press finishes the purchase. It shares the checkout's entry slot with the checkout element: a handle mounts exactly one of the two. Two options shape it: `wallets` picks which wallet buttons may render (a filter over what the buyer's device actually offers — the element never shows a wallet the device can't pay with), and `layout` controls how the buttons stack (`auto` follows the container, `horizontal` and `vertical` force one arrangement). ([#24974](https://github.com/whopio/whop-monorepo/pull/24974))
- c486df4: Added `destroy()` to namespace handles — tear down a checkout (or any element group) when you are done with it, freeing its elements, frames, and subscriptions. React groups keep doing this automatically when the provider unmounts. ([#24974](https://github.com/whopio/whop-monorepo/pull/24974))
- c486df4: Apple Pay and Google Pay sheets opened from an express checkout button now take promo codes: the sheet shows its own promo entry when the seller offers codes, prices the code before the buyer authorizes, and applies it with the payment. A code already applied to the checkout appears in the sheet and can be removed there. ([#24974](https://github.com/whopio/whop-monorepo/pull/24974))
- c486df4: `paymentRequest.canMakePayment()` now also returns `order` — the wallets ranked by which sheet is native to the browser (Apple Pay first on Safari, Google Pay first elsewhere), so express buttons can be stacked best-first. ([#24974](https://github.com/whopio/whop-monorepo/pull/24974))
- c486df4: The wallet cards element tells you what to do when there are no cards. An account with no card program is offered account verification instead of a retry message that could never work — the press starts the hosted verification session and leaves for it, emitting `verificationRequested` so a host can record the trip. A provisioned account with no cards yet gets an invitation to create its first one, with a placeholder row where it will sit. Genuine transient failures keep the retry message. ([#24974](https://github.com/whopio/whop-monorepo/pull/24974))

### Patch Changes

- c486df4: The ads billing slots show a balance the account funds ads with even when the viewer has no access to that balance themselves — it renders with the balance's own name and icon instead of reading as an empty slot, and the other slot can be changed without the save being refused. ([#24974](https://github.com/whopio/whop-monorepo/pull/24974))
- c486df4: Apple Pay reports itself available only where a payment can actually finish. A page whose origin isn't approved for the account reports it unavailable — matching Google Pay, and matching what the payment sheet itself would do at merchant validation; first-party whop.com pages are pre-approved, and a merchant page needs its domain registered as a payment method domain. Mobile non-WebKit browsers report it unavailable too — the cross-browser flow there is the desktop handoff, which a phone can't sensibly complete. Native Apple Pay in iOS browsers is unaffected. ([#24974](https://github.com/whopio/whop-monorepo/pull/24974))
- c486df4: Bank transfer instruction steps now show the receiving bank's code even when the bank's name is not supplied, so buyers paying by IBAN get the BIC alongside the account number instead of only a reference. ([#24974](https://github.com/whopio/whop-monorepo/pull/24974))
- c486df4: `SendElement` now authenticates with the `accessToken` it is given. Every call it made — the recipient list, recipient search, the account balance on the amount screen, and the transfer itself — went out with no credential, so the element only worked on a page that already carried a Whop session cookie and refused with 401 everywhere else. ([#24974](https://github.com/whopio/whop-monorepo/pull/24974))
- c486df4: Checkout and payment elements now hide Bank Wire when the current plan or promo code cannot use it. ([#24974](https://github.com/whopio/whop-monorepo/pull/24974))
- c486df4: The embedded checkout no longer grows taller on every resize when appearance styles add padding or a border around the element — embedded frames now size to the checkout content, and the full-page checkout layout is unchanged. For the same reason, appearance styles can no longer size an element's growth from the viewport: heights (any fraction — even `50vh`), padding, margins, borders, gaps, font sizes, line heights, and flex bases with viewport-unit values (`vmin` excepted), or reached through `var()` or `calc()`, are dropped on those properties, and appearance variables no longer accept viewport-height units at all. `max-height` caps still work, and the framework's `--whop-viewport` variable cannot be redefined through appearance. ([#24974](https://github.com/whopio/whop-monorepo/pull/24974))
- c486df4: Passing an `email` to `paymentRequest.show()` now tells the wallet sheet you already collected one, so the sheet no longer asks the buyer for a second email. Omit it and the sheet collects one, exactly as before. ([#24974](https://github.com/whopio/whop-monorepo/pull/24974))
- c486df4: A promo code that makes a checkout entirely free no longer strands the buyer on an empty payment-method list: fully free checkouts skip payment collection, and $0-today checkouts offer methods judged against the first charge that takes money. A checkout with nothing to pay also stops advertising adaptive pricing — free plans, membership transfers, and checkouts a promo code makes entirely free drop the "pay in another currency" switch and the conversion note, and always price in the seller's own currency. - c486df4: SEPA Debit checkout fields now load reliably when card is also offered, so buyers can enter their bank account details after switching payment methods. ([#24974](https://github.com/whopio/whop-monorepo/pull/24974))
- c486df4: `font-family` declarations in `appearance.classes` now apply — font name lists like `Georgia, 'Times New Roman', serif` are accepted, quoted or unquoted. ## 1.0.0-beta.0

### Major Changes

- 5deffbd: Initial release of Whop Elements — embeddable Whop UI for any website. Drop the `elements.js` script tag (or install `@whop/elements`) and mount ready-made, themeable components that talk to Whop for you; `@whop/elements-react` ships first-class React bindings on top. This first release includes the full foundation: typed handles with live `update()`, events and actions; light/dark theming and appearance customization; localized components; prerendered loading skeletons for flash-free first paints; modal and inline flow surfaces; and generated TypeScript types for the entire surface. ([#23567](https://github.com/whopio/whop-monorepo/pull/23567))
- 5deffbd: Removed the campaign builder's `showToasts` prop and `errored` event. Failure toasts now always appear exactly once through the standard toast surface — on your own page when the builder is embedded — so there is nothing left to mirror or turn off. ([#23567](https://github.com/whopio/whop-monorepo/pull/23567))
- 5deffbd: Choose which Whop environment your elements run against when you create them: `WhopElements({ environment: 'sandbox' })` uses test data with no real money moving, and production is the default. This is the one setting that decides where the elements send what a buyer enters — they only ever talk to Whop. ([#23567](https://github.com/whopio/whop-monorepo/pull/23567))

### Minor Changes

- 5deffbd: The embedded campaign builder shows the merchant when something fails: a refused launch, a failed upload or a draft that would not save renders as a toast in the builder itself, and comes back on an `errored` event if your page wants to log it or show it its own way. ([#23567](https://github.com/whopio/whop-monorepo/pull/23567))
- 5deffbd: Checkout element: buyers are charged in their own currency, not shown a converted price. The server picks the currency from where the checkout was opened and publishes the one alternative as a "Pay in USD instead" switch. A converted total discloses what it converted from and at what locked rate, to five significant digits ("1 USD = 0.92191 EUR"), and when a promo code is applied the original price is struck through in the currency the buyer actually pays. ([#23567](https://github.com/whopio/whop-monorepo/pull/23567))
- 5deffbd: How a checkout finishes: when you set a `returnUrl`, a completed purchase redirects the page the element is embedded in straight to it — fulfill from webhooks, which are the source of truth for a landed payment — and a page whose sandbox blocks that navigation gets a Continue button that makes the same trip. A payment step that leaves the page, like 3D Secure or a bank page, carries the buyer back to a page that tells them exactly where the order stands. Completion is judged by the payment's own status: a payment that settles later, like a bank debit, shows clearing copy while the money is still moving and only sends the buyer on once it has genuinely settled, and a dismissed 3D Secure dialog rests on a "Finish your payment" button. ([#23567](https://github.com/whopio/whop-monorepo/pull/23567))
- 5deffbd: Added the tax ID element to the payments namespace: a standalone registration collector with a type select covering every registration the API accepts — labeled the way buyers know them (EU VAT, AR CUIT, US EIN, …) — and a value input whose placeholder follows the selected type. When you pass the buyer's country it preselects the right type. The checkout element's company-purchase section composes it, so a business buyer can enter any accepted tax ID at checkout: the total re-prices with the reverse charge applied where it applies, and the charge is taxed under the same registration. ([#23567](https://github.com/whopio/whop-monorepo/pull/23567))
- 5deffbd: The checkout element says what the two special checkouts actually are. Opening a transfer link states in the order summary that you are accepting an existing membership — nothing is charged today, when the inherited access ends, and when the payment method you add first renews. A waitlist join tells the whole truth about money: the total reads "If accepted" rather than "Due today", the terms explain the buyer is only charged if the seller accepts their request, and a completed join says you are on the waitlist — the seller reviews requests, and the saved payment method is only charged if they accept you — both inside the element and on the hosted return page.
