# @whop/elements

## 1.0.0-beta.0

### Major Changes

- 5deffbd: Initial release of Whop Elements — embeddable Whop UI for any website. Drop the `elements.js` script tag (or install `@whop/elements`) and mount ready-made, themeable components that talk to Whop for you; `@whop/elements-react` ships first-class React bindings on top. This first release includes the full foundation: typed handles with live `update()`, events and actions; light/dark theming and appearance customization; localized components; prerendered loading skeletons for flash-free first paints; modal and inline flow surfaces; and generated TypeScript types for the entire surface. ([#23567](https://github.com/whopio/whop-monorepo/pull/23567))
- 5deffbd: Removed the campaign builder's `showToasts` prop and `errored` event. Failure toasts now always appear exactly once through the standard toast surface — on your own page when the builder is embedded — so there is nothing left to mirror or turn off. ([#23567](https://github.com/whopio/whop-monorepo/pull/23567))
- 5deffbd: Choose which Whop environment your elements run against when you create them: `WhopElements({ environment: 'sandbox' })` uses test data with no real money moving, and production is the default. This is the one setting that decides where the elements send what a buyer enters — they only ever talk to Whop. ([#23567](https://github.com/whopio/whop-monorepo/pull/23567))

### Minor Changes

- 5deffbd: The embedded campaign builder shows the merchant when something fails: a refused launch, a failed upload or a draft that would not save renders as a toast in the builder itself, and comes back on an `errored` event if your page wants to log it or show it its own way. ([#23567](https://github.com/whopio/whop-monorepo/pull/23567))
- 5deffbd: Checkout element: buyers are charged in their own currency, not shown a converted price. The server picks the currency from where the checkout was opened and publishes the one alternative as a "Pay in USD instead" switch. A converted total discloses what it converted from and at what locked rate, to five significant digits ("1 USD = 0.92191 EUR"), and when a promo code is applied the original price is struck through in the currency the buyer actually pays. ([#23567](https://github.com/whopio/whop-monorepo/pull/23567))
- 5deffbd: How a checkout finishes: when you set a `returnUrl`, a completed purchase redirects the page the element is embedded in straight to it — fulfill from webhooks, which are the source of truth for a landed payment — and a page whose sandbox blocks that navigation gets a Continue button that makes the same trip. A payment step that leaves the page, like 3D Secure or a bank page, carries the buyer back to a page that tells them exactly where the order stands. Completion is judged by the payment's own status: a payment that settles later, like a bank debit, shows clearing copy while the money is still moving and only sends the buyer on once it has genuinely settled, and a dismissed 3D Secure dialog rests on a "Finish your payment" button. ([#23567](https://github.com/whopio/whop-monorepo/pull/23567))
- 5deffbd: Added the tax ID element to the payments namespace: a standalone registration collector with a type select covering every registration the API accepts — labeled the way buyers know them (EU VAT, AR CUIT, US EIN, …) — and a value input whose placeholder follows the selected type. The checkout element's company-purchase section composes it, so a business buyer can enter any accepted tax ID at checkout: the total re-prices with the reverse charge applied where it applies, and the charge is taxed under the same registration. ([#23567](https://github.com/whopio/whop-monorepo/pull/23567))
- 5deffbd: The checkout element says what the two special checkouts actually are. Opening a transfer link states in the order summary that you are accepting an existing membership — nothing is charged today, when the inherited access ends, and when the payment method you add first renews. A waitlist join tells the whole truth about money: the total reads "If accepted" rather than "Due today", the terms explain the buyer is only charged if the seller accepts their request, and a completed join says you are on the waitlist — the seller reviews requests, and the saved payment method is only charged if they accept you — both inside the element and on the hosted return page. A completed join is also announced to an embedding iOS/Android app so its checkout sheet closes. ([#23567](https://github.com/whopio/whop-monorepo/pull/23567))
- 5deffbd: The activity list now reports the row under the pointer (`activityHovered`), and the balance chart takes a `markedAt` timestamp to mark that moment on the line — so hovering a transaction shows where it sits in the balance history.
